# Amadeus：世界线观测与推演型 Agent-RAG 智能体项目报告

> 当前版本：Phase 2 - Worldline RAG  
> 更新日期：2026 年 9 月 20 日  
> 项目方向：Agent / RAG / 角色化交互 / 反事实推演

## 1. 项目概述

**项目名称**：Amadeus：世界线观测与推演型 Agent-RAG 智能体

**一句话定位**：把用户上传的历史、科学、动漫设定或原创人物经历作为“世界线档案”，由角色化 Agent 检索证据、识别分歧点，并生成可解释的因果推演或沉浸式分支叙事。

Amadeus 以《命运石之门》中“数字化人格”的概念为灵感，采用 **FastAPI + Vue 3 + LangGraph + LangChain + ChromaDB + GPT-SoVITS** 构建。它既可以进行自然对话、调用工具和管理个人知识库，也可以围绕“如果某个关键事件没有发生，之后会怎样”这一类问题进行世界线推演。

项目的核心不再只是“让模型扮演一个角色”，而是将以下能力组合为完整应用：

- **Agent**：理解意图并自主调用时间、计算、知识库、网页、邮件等工具。
- **RAG**：从用户上传的资料中检索与当前分歧点有关的事实和设定。
- **世界线引擎**：把原始进程、分歧点、约束条件和连锁影响组织成推演。
- **角色化交互**：以 Amadeus 人格、视觉工作台和角色语音呈现结果。
- **工程化前后端**：提供流式响应、文件管理、状态面板、会话记忆和异常恢复。

## 2. 项目背景与问题

通用大模型可以直接回答反事实问题，但它通常存在三个问题：

1. **参考基线不稳定**：模型可能混淆史实、作品设定和网络二创。
2. **推演过程不可控**：答案容易只给一个“听起来合理”的结论，缺少分歧点和因果链。
3. **私有设定不可知**：原创人物经历、班级案例或用户自己编写的世界观不在模型参数中。

本项目使用 RAG 保存“原始世界线资料”，在回答前检索相关片段，再由 Agent 结合提示词规则进行推演。RAG 的作用不只是规范语气，而是给模型提供一份可更新、可替换、可追溯的推演依据。

例如，用户上传“林默的成长经历”后，可以设置“初二时家人同意参加艺考”为分歧点。系统先检索原始经历和人物约束，再分别分析学业路径、家庭关系、经济压力、专业训练和心理状态可能产生的变化，而不是凭空替人物编写一段固定结局。

## 3. 核心体验：双模式世界线推演

### 3.1 观测模式

观测模式面向理性分析，适合历史事件、科学史、作品剧情和个人发展路径。

```text
用户设置分歧点
→ Agent 强制检索知识库
→ 还原原始世界线与已知约束
→ 区分事实、资料缺口与合理假设
→ 分析直接影响、二阶影响和长期影响
→ 输出候选世界线及不确定性
```

观测模式不会提升或降低模型本身的“精度档位”。它改变的是任务提示词、检索要求和输出结构，使模型优先做证据约束下的因果分析。

### 3.2 沉浸模式

沉浸模式面向情境体验。在检索相同背景资料后，系统以场景、行动和对话讲述另一条世界线，并在结尾说明关键变化和下一个可继续选择的分歧点。

```text
知识检索
→ 人物与时代约束
→ 场景化叙事
→ 世界线变动率提示
→ 关键变化回收
→ 下一分歧点
```

| 对比项 | 观测模式 | 沉浸模式 |
|---|---|---|
| 目标 | 分析“为什么会变化” | 体验“变化后的世界” |
| 表达 | 因果链、约束、不确定性 | 场景、行动、对白 |
| 适用 | 汇报、研究、讨论、教学 | 故事体验、角色互动、创作 |
| RAG | 必须先检索 | 必须先检索 |
| 模型能力 | 相同 | 相同 |

## 4. 知识库设计

### 4.1 当前示例资料

项目已经准备并可上传以下类型的世界线资料：

- 世界线推演方法与使用说明
- 《命运石之门》世界线规则、关键事件时间线、人物与动机
- 牛顿与经典力学、爱因斯坦与相对论、图灵与计算机发展
- 原创人物“林默”的艺考分支世界线

这些文件证明知识库不仅能存教材和公司文档，也能存储“人物历史进程 + 已知约束 + 关键节点 + 可选分支”。

### 4.2 文档入库流程

```text
上传 PDF / DOCX / TXT / MD / CSV / JSON
→ 计算 MD5 并去重
→ 提取文本
→ 递归切分为知识片段
→ BGE 中文向量化
→ 写入 ChromaDB
→ SQLite 记录文件元数据
```

### 4.3 两条 RAG 链路

**标准 RAG 问答**：用户在知识库面板直接提问，系统检索片段并返回答案和来源，适合资料核对与实训验收。

**Agent-RAG 对话**：用户在主对话区发问，LangGraph Agent 自主决定调用 `search_knowledge_base`，再以角色语气组织结果，适合自然对话和世界线推演。

## 5. 系统架构

```text
Vue 3 角色工作台
├── 知识库：上传、列表、删除、RAG 问答
├── 角色舞台：立绘、状态、音频响应、Live2D 预留
├── 对话控制台：SSE 文本、工具事件、双模式开关
└── 系统监视器：会话、工具、知识片段、角色状态
        │
        ▼
FastAPI API / WebSocket
├── LangGraph ReAct Agent
│   ├── DeepSeek / Qwen
│   ├── 工具决策与执行
│   ├── AsyncSqliteSaver 会话记忆
│   └── 中断工具历史自动修复
├── RAG 服务
│   ├── KnowledgeBaseService
│   ├── VectorStoreService
│   └── RagService（Prompt + LCEL + Parser）
└── 语音服务
    ├── FunASR 中文语音识别
    ├── 中文到日文翻译
    └── GPT-SoVITS 角色语音合成
```

## 6. 技术栈

| 模块 | 技术选型 | 作用 |
|---|---|---|
| 前端 | Vue 3 + Vite | 三栏角色工作台和响应式交互 |
| 后端 | FastAPI | REST、SSE 和 WebSocket 接口 |
| Agent | LangGraph `create_react_agent` | ReAct 决策、工具调用与状态流转 |
| RAG | LangChain LCEL | Prompt、检索上下文和输出解析 |
| LLM | DeepSeek / Qwen | 对话生成、工具决策和推演 |
| 向量库 | ChromaDB | 文档向量持久化与语义检索 |
| Embedding | BAAI/bge-small-zh-v1.5 | 中文文本向量化 |
| 会话记忆 | SQLite + AsyncSqliteSaver | 多会话状态持久化 |
| 语音识别 | FunASR Paraformer | 中文语音转文字 |
| 语音合成 | GPT-SoVITS | 日语角色音色输出 |
| 通信 | SSE + WebSocket | 流式文本、工具事件与语音通道 |

## 7. 已实现功能

### 7.1 角色化自然对话

- Amadeus 人格提示词和自然短句风格
- 普通对话与世界线长回答分离
- 自动换行和 Markdown 装饰清理
- DeepSeek / Qwen 提供商切换
- 多轮会话和用户画像提取

### 7.2 Agent 工具系统

| 工具 | 能力 |
|---|---|
| `get_current_time` | 获取真实时间与日期 |
| `calculate` | 数学计算 |
| `create_reminder` | 创建提醒 |
| `send_email` | 发送邮件 |
| `search_knowledge_base` | 检索知识库 |
| `add_to_knowledge_base` | 写入长期知识 |
| `delete_from_knowledge_base` | 安全删除知识 |
| `search_web` | 搜索最新信息 |
| `fetch_text_from_url` | 读取网页正文 |

工具调用通过 SSE 显示开始、完成和异常状态，用户可以看到 Agent 正在使用什么能力。

### 7.3 新版前端工作台

页面已由早期单一聊天界面升级为三栏工作台：

- 左侧：知识库上传、文件列表、删除和 RAG 问答。
- 中部：角色舞台、状态反馈和主要对话区。
- 右侧：运行状态、会话计数、工具计数和知识片段统计。
- 底部：世界线开关、观测/沉浸分段控件、语音与快捷操作。
- 移动端：保留响应式布局和可用的核心交互。

### 7.4 语音与角色状态

系统已接入 FunASR 中文语音识别与 GPT-SoVITS 日语角色语音。角色控制器统一管理 `idle`、`thinking`、`tool`、`listening`、`speaking`、`error` 状态，并让立绘光效与音频电平联动。

当前渲染器为静态立绘，但 `CharacterStage` 已通过 `renderer`、`model-id`、状态和音频电平建立渲染器中立接口。后续接入 Live2D 时可以替换角色渲染层，不需要重写聊天、RAG 和状态逻辑。

### 7.5 稳定性与可维护性

- 修复被中断工具调用导致的 LangGraph 无效历史。
- 将 SSE 文本封装为 JSON，保留模型自然换行。
- 后端退出时主动关闭 SQLite 连接和 STT 工作进程。
- 日常启动取消 Uvicorn `--reload`，避免 Windows 残留父子进程。
- 新增 `stop_amadeus.bat`，按项目端口结束完整进程树。
- 当前自动化验证：后端 12 项测试、前端 22 项测试。

## 9. 启动与停止

### 9.1 后端

```powershell
cd D:/amadeus
D:/miniconda3/python.exe -m uvicorn backend.app.main:app --port 8000
```

日常运行不使用 `--reload`。热重载只用于明确需要自动重载代码的开发场景。

### 9.2 前端

```powershell
cd D:/amadeus/frontend
npm run dev
```

浏览器访问：`http://localhost:5173`

### 9.3 语音服务（可选）

```powershell
D:/conda_envs/sovits/python.exe D:/amadeus/start_sovits_api.py
```

### 9.4 完全停止

双击项目根目录的 `stop_amadeus.bat`。脚本会结束占用 `5173`、`8000`、`9880` 的项目进程树。

## 10. 项目特色与答辩亮点

1. **不是普通聊天机器人**：Agent 能自主使用工具并展示执行过程。
2. **不是普通文件问答**：RAG 被用于世界线基线、人物约束和分歧点证据。
3. **双模式推演**：同一份资料既能做理性因果分析，也能做沉浸式叙事。
4. **支持原创人物世界线**：用户可以自建人物历史，而不局限于公开历史或动漫 IP。
5. **角色状态与业务解耦**：静态立绘可以逐步替换为 Live2D。
6. **有完整工程链路**：前端、API、向量库、会话记忆、语音和退出清理均已形成闭环。
7. **可解释性较强**：展示工具调用、知识文件、来源和资料缺口，而非只给结论。

## 11. 商业化落地方向

### 11.1 世界线创作与 IP 互动

面向动漫、游戏、小说和虚拟角色，提供“选择一个分歧点并继续世界”的互动体验。商业版本需要使用原创角色或获得 IP、立绘与声线授权。

### 11.2 教学型反事实实验室

面向历史、科学史、社会学和写作课程，让学生上传资料、设置变量并比较不同因果链。教师可以检查引用、假设和推演依据。

### 11.3 个人成长路径沙盘

用户录入个人经历、目标、资源和限制，比较“继续当前选择”与“采取另一方案”的可能路径。产品必须明确这是辅助思考而非确定性预测。

### 11.4 企业情景推演助手

将企业制度、产品资料、市场事件和业务约束写入私有知识库，用于新品策略、危机预案和运营情景讨论。需要补充权限、审计、多租户和数据隔离。

### 11.5 可售卖能力

- 世界线主题知识包
- 原创角色与 Live2D 形象包
- 私有知识库空间
- 团队协作与推演报告导出
- 高级模型、语音和长上下文配额
- 私有化部署与企业定制

## 13. 总结

Amadeus 已从早期角色聊天 Demo 演进为一个具有明确主题的世界线推演产品原型。它用 RAG 保存“原本发生了什么”，用 Agent 决定“需要查什么、调用什么”，再通过观测或沉浸模式回答“如果改变一个节点，世界可能如何继续”。

当前版本已经具备答辩演示所需的完整主链路：

```text
上传世界线资料
→ 设置分歧点
→ Agent 检索证据
→ 观测分析或沉浸叙事
→ 展示工具过程与角色反馈
```

下一阶段最重要的目标不是继续堆功能，而是完成一键启动、Live2D、推演结果引用与评测体系，并选择教育、互动创作或企业情景推演中的一个场景做深，形成可长期使用和可商业交付的产品。
